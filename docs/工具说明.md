# 工具说明

## 工具总览

| 环节 | 工具 / 入口 | 作用 | 主要输出 |
| --- | --- | --- | --- |
| 烘焙 | `NTC / Bake Window` | 扫描源材质，转换贴图，生成 manifest，调用 CLI 训练并发布资产 | `.ntc`、解压预览、绑定资产与材质模板 |
| 已有数据绑定 | `Assets / NTC / Bind Existing NTC To Material` | 为选中的 Material 关联已有 `.ntc` | GUID 绑定资产 |
| 场景配置 | `NTC / Add Scene Controller`、`NTC / Rescan Scene Materials` | 创建控制器、扫描全部材质槽、保存场景绑定 | `NtcSceneController` 及其材质组 |
| 本地示例准备 | `NTC / Prepare Showcase Bindings` | 配置示例场景、迁移旧文件名绑定、设置 shader 引用与构建场景 | 已配置的示例场景 |
| 运行时观察 | Scene Controller 的 F1 面板 | 切换模式、查看通道、材质状态及资源统计 | 屏幕调试视图 |
| 材质截图 | `NtcLifecycleValidationRunner` | 绘制独立材质探针，保存首次与再次绘制的图像 | PNG、`lifecycle.json` |
| 通道对照图 | `NtcDirectMaterialTests` + `NTC_TEST_CAPTURE_DIR` | 导出 Direct 与解码贴图后端的逐通道图像 | 成对 PNG |
| GPU 抓帧 | Player 参数 `-ntcBenchmarkRenderDocCapture` | 通过 RenderDoc 捕获 tile 解码和场景绘制所在帧 | `.rdc` |
| 文件检查 | `NtcContainerReader`、`NtcPackingReport` | 解析 NTEX、查看通道、网络层、mip 和 BufferView | 代码中的容器对象与文本报告 |
| 工程同步 | `Prepare-NtcShowcase.ps1` | 同步插件、配置本地包、调用示例准备入口 | 项目文件、同步状态、备份及日志 |
| 自动测试 | `Run-NtcEditModeTests.ps1` | 创建测试宿主并运行 Unity Test Runner | XML、Editor 日志，可选 PNG |
| Player 运行 | `Run-NtcBenchmark.ps1` | 构建并依次运行四种模式，记录状态和采样数据 | JSON、CSV、Player 日志 |
| 插件打包 | `Export-NtcPackage.ps1` | 导出代码、shader、测试和许可证 | UPM 目录结构的 ZIP |

下面按实际使用场景说明。表中的自动测试和构建工具随源码提供，测试输出及本地运行记录保存在工作目录。

## 烘焙与材质绑定

Bake Window 的常用操作：

| 按钮 | 作用 |
| --- | --- |
| `Scan Scene Materials` | 收集场景中所有 Renderer 材质槽，按材质对象去重 |
| `Bake` / `Rebake` | 处理单个材质 |
| `Bake All Selected` | 依次处理选中的材质 |
| `Select Unbaked` | 选择尚无压缩输出的材质 |
| `Select Baked (Rebake)` | 选择已有输出、准备重新烘焙的材质 |
| `Bind Existing Selected` | 使用所选条目的已有文件创建或更新绑定 |

`Output dir` 存放压缩结果和 `Decompressed/<GUID_localId>/` 预览。CLI 控制台输出显示在窗口下方。烘焙参数、通道提取和最终发布目录见 [使用说明](使用说明.md#烘焙)。

选中 Material 后，右键菜单 `Assets / NTC / Bind Existing NTC To Material` 可手动选择已有数据。`NtcTextureSetAsset` 保存数据、模板和原材质恢复路径；Controller 的 Rescan 将这些资产关联到对应 Renderer 材质槽。

## 场景配置与调试面板

Controller 的 Inspector 提供 `Rescan Scene Materials` 和 `Open Bake Window`，并列出材质组、Renderer 数量和绑定位置。

进入 Play 后，按 **F1** 显示或隐藏面板。`togglePanelKey` 可修改快捷键。

| 面板项 | 作用 |
| --- | --- |
| `Original` | 使用源材质 |
| `on-Load` | 切到整图解码贴图 |
| `on-Sample` | 切到 tile cache |
| `Direct Lit` | 切到 fragment PBR 推理 |
| `Lit` | 查看完整着色 |
| `Base` / `Normal` / `Metal` / `Rough` | 单独查看颜色、法线、金属度和粗糙度 |
| `Materials` | 查看各材质组的加载状态、Renderer 数量及回退原因 |
| `Stats` | 查看磁盘数据和原图、latent、权重、缓存的分类占用 |
| `ColorSpace: Auto / Force sRGB / Force Raw` | 对 Compute 解码及旧 fragment 后端做颜色转换对照；Direct 使用自己的材质色彩处理 |

tile 调度参数位于 Controller：`streamTileSize` 控制块尺寸，`streamCapResolution` 控制缓存分辨率，`streamBudgetTilesPerFrame` 控制每帧处理块数，`streamEvictSeconds` 控制不可见后的回收时间。

## 截图与抓帧

### 场景画面：NVIDIA Renderer 的 Save Screenshot

NVIDIA SDK 的独立 Renderer 加载 glTF 模型及其 NTC 材质。界面中的 **Save Screenshot** 保存当前渲染画面，文件扩展名决定格式，支持 `.bmp`、`.png`、`.jpg` 和 `.tga`。

这一入口用于保存 NVIDIA Renderer 中的模型画面。模型准备、材质目录和相机操作见 [官方 Renderer 指南](https://github.com/NVIDIA-RTX/RTXNTC/blob/1cfa9a514d1b893754df0d343e0dd9cf5a11567d/docs/Renderer.md)。

### Unity 材质探针图

`NtcLifecycleValidationBuild.BuildWindows64` 生成一个小型 Player，其中 `NtcLifecycleValidationRunner` 自动切换材质并绘制探针。它同时处理共享原图的保留、回收和恢复检查。

运行构建后的专用 Player：

```powershell
& '<LifecyclePlayer.exe>' -force-d3d12 -ntcLifecycleOutput '<output directory>'
```

输出：

| 文件 | 内容 |
| --- | --- |
| `direct-lit-probe.png` | 首次 Direct 材质绘制的 64×64 离屏图 |
| `direct-lit-probe-warm.png` | 同一材质再次绘制的图 |
| `lifecycle.json` | 各阶段资源状态和绘制计时 |

这些 PNG 显示独立材质探针。该专用场景由构建入口创建，使用本地示例中的 `Column_A` 绑定。

### Unity 通道对照图

为测试脚本设置图像输出目录：

```powershell
$env:NTC_TEST_CAPTURE_DIR = Join-Path $PWD 'build/channel-images'
.\tools\Run-NtcEditModeTests.ps1 -UnityEditor '<Unity.exe>' -Corpus '<corpus>'
$env:NTC_TEST_CAPTURE_DIR = $null
```

`NtcDirectMaterialTests` 会保存 `direct-view<编号>-<Filter>.png` 和 `decoded-view<编号>-<Filter>.png`。两张图分别来自 Direct 推理和解码贴图采样后端。

| view 编号 | 内容 |
| --- | --- |
| 0 | 完整 PBR 着色 |
| 1 | BaseColor |
| 2 | Normal |
| 3 | Metallic |
| 4 | Roughness |
| 5 | AO |

过滤方式包括 Point、Bilinear 和 Trilinear，文件名按 view 与 filter 组合生成。同名输出由后续用例更新。这组图用于检查材质通道和采样；实际场景画面由场景相机产生。

### RenderDoc 帧捕获

RenderDoc 用来检查一帧中的 draw、compute dispatch、资源绑定和 shader。输出 `.rdc` 可在 RenderDoc 中逐事件查看。

1. 在 RenderDoc 的 Launch Application 中选择构建后的 Unity Player。
2. 设置以下 Player 参数并启动：

   ```text
   -force-d3d12 -ntcBenchmark -ntcBenchmarkRenderDocCapture -ntcBenchmarkOutput "<output directory>"
   ```

3. Runner 在 `InferenceOnSample` 阶段选择 tile 解码仍在进行的一帧，跨过下一次 Update 后结束捕获。
4. 在 `<output directory>/renderdoc/` 打开文件名前缀为 `ntc-onsample` 的 `.rdc`。

Player 需要由 RenderDoc 注入 `renderdoc.dll`；该参数只触发捕获，不负责注入。`benchmark.json` 的 `renderDocCaptureSucceeded`、`renderDocCaptureStatus` 和 `renderDocCapturePathTemplate` 记录捕获状态与位置。

## 命令行脚本

所有 PowerShell 示例从仓库根目录执行。`-UnityEditor` 传入本机 Unity Editor 可执行文件的完整路径。

### Prepare-NtcShowcase.ps1

用于同步插件并配置已有的本地 Unity 示例工程：

```powershell
.\tools\Prepare-NtcShowcase.ps1 -UnityEditor '<Unity.exe>' -Project '<project>' `
  -Scene 'Assets/Scenes/Demo.unity' -PipelineAsset 'Assets/Settings/URP.asset'
```

| 参数 | 作用 |
| --- | --- |
| `-Project` / `-Scene` | 指定已有工程和场景；默认工程为仓库的 `unity-showcase` |
| `-PipelineAsset` | 指定 URP 资产 |
| `-LegacyDirectory` | 指定旧 NTC 文件的迁移来源 |
| `-InitialMode` | 保存场景时设置初始模式 |
| `-ReleaseOriginalTextures` | 设置控制器的原图引用释放选项 |
| `-SyncOnly` | 只同步插件及所选包配置 |
| `-InitializePluginMirror` | 先备份已有镜像文件，再初始化或替换镜像 |
| `-UseBundledPackages` | 使用指定 Editor 随附的 URP/core/shadergraph 包 |
| `-RegistryUrl` | 设置该项目的 Unity 包 registry |

默认场景为 `Assets/ClassicSponza/Scenes/Sponza_Showcase.unity`；其他场景通过 `-Scene` 指定。源代码同步到目标工程的 `Assets/NtcPlugin`。镜像 hash 存在 `ProjectSettings/NtcPluginMirror.json`，被替换的文件备份到仓库 `build/prepare-backups`，准备日志位于 `build/prepare-results/unity-prepare.log`。

### Run-NtcEditModeTests.ps1

```powershell
.\tools\Run-NtcEditModeTests.ps1 -UnityEditor '<Unity.exe>' -CpuOnly
.\tools\Run-NtcEditModeTests.ps1 -UnityEditor '<Unity.exe>' -Corpus '<corpus>'
```

`-CpuOnly` 使用 Null 图形设备运行基础子集；`-Corpus` 指定完整模型测试使用的25文件目录，其中包含既定的 `Bricks.ntc`、`Flagpoles.ntc` 等模型。`-ProjectPath` 指定一次性测试宿主，默认是 `build/ntc-review-tests`；脚本会配置其 manifest 和插件镜像。`-UrpVersion` 用于不随附 URP 的 Editor，`-RegistryUrl` 指定包源。

输出为宿主目录下的 `editmode-results.xml` 和 `editmode.log`；设置 `NTC_TEST_CAPTURE_DIR` 后还会导出上述通道图。

### Run-NtcBenchmark.ps1

为指定场景构建 Player，并按 `Original → InferenceOnLoad → InferenceOnSample → InferenceOnSampleDirect` 顺序运行：

```powershell
.\tools\Run-NtcBenchmark.ps1 -UnityEditor '<Unity.exe>' -Project '<project>' `
  -Scene 'Assets/Scenes/Demo.unity' -SkipPrepare -Output '<output directory>'
```

| 参数 | 作用 |
| --- | --- |
| `-SkipBuild -Player '<exe>'` | 运行已有 Player |
| `-SkipPrepare` | 使用已经配置好的场景 |
| `-Modes` | 逗号分隔的运行模式列表 |
| `-WarmupFrames` / `-SampleFrames` | 每种模式的预热和采样帧数 |
| `-ResourceOnly` | 运行资源与 GPU 队列检查 |
| `-Output` | 指定 JSON、CSV 和日志目录 |

默认输出目录是 `build/benchmark-results`，默认 Player 是 `build/NTCinUnity-Benchmark/NTCinUnity.exe`。脚本隐藏启动 Player；默认模式要求相机渲染，`-ResourceOnly` 允许只进行资源检查。

| 文件 | 内容 |
| --- | --- |
| `benchmark.json` | 模式状态、材质组、资源、相机帧及采样摘要 |
| `summary.csv` | 每模式统计 |
| `frames.csv` | 每个样本的数据 |
| `player.log` | Player 日志 |
| `unity-build.log` | 本次构建日志；跳过构建时不生成 |

### Export-NtcPackage.ps1

```powershell
.\tools\Export-NtcPackage.ps1
.\tools\Export-NtcPackage.ps1 -Output '<package.zip>'
```

默认导出 `build/NTC-Unity-<version>.zip`。包含 Runtime、Editor、Resources、Shaders、Tests、package.json、Unity metadata 和许可证；本地说明、工作记录、NtcData、示例美术、SDK 和 IDE 文件不进入包。

## Editor 批处理与代码入口

以下名称用于 Unity 的 `-executeMethod`：

| 方法 | 作用 | 常用参数 |
| --- | --- | --- |
| `Ntc.UnityEditorTools.NtcShowcasePreparation.Prepare` | 配置示例场景和材质绑定 | `-ntcBenchmarkScene`、`-ntcPipelineAsset`、`-ntcLegacyDirectory`、`-ntcInitialMode` |
| `Ntc.Unity.EditorTools.NtcBenchmarkBuild.BuildWindows64` | 构建指定场景的 Windows x64/D3D12 Player | `-ntcBenchmarkScene`、`-ntcBenchmarkPlayer` |
| `Ntc.UnityEditorTools.NtcLifecycleValidationBuild.BuildWindows64` | 创建并构建材质探针小场景，使用 `Column_A` 绑定 | `-ntcLifecyclePlayer` |
| `Ntc.UnityEditorTools.NtcAcceptanceBuild.BuildAll` | 依次准备示例并构建小场景和正式场景 Player | 上述场景、管线和两个输出路径 |

示例：

```powershell
& '<Unity.exe>' -batchmode -quit -projectPath '<project>' `
  -executeMethod Ntc.Unity.EditorTools.NtcBenchmarkBuild.BuildWindows64 `
  -ntcBenchmarkScene 'Assets/Scenes/Demo.unity' -ntcBenchmarkPlayer '<Player.exe>'
```

构建过程中 `NtcPlayerData` 汇总场景需要的 NTC 文件，检查生成 Player 中的数据并剔除未使用文件；处理范围是生成的 Player 数据目录。

文件结构检查通过代码 API 调用：`NtcContainerReader.Load(path)` 解析 `.ntc`，`NtcPackingReport.Build(fileName, container)` 返回网络层、通道、mip、latent 和 BufferView 的文本摘要。

## 单机位 A/B 展示

`NtcShowcaseBuild.BuildWindows64` 从已配置的场景另存展示副本，并构建独立 Player。界面只保留 A Original、B NTC、Forward/Pause 和 Reset。`1`、`2` 切换材质，空格暂停，Home 回到起点；切换材质时暂停机位以便比较。

展示使用同一条向前路径，两种材质使用相同机位、光线和色调映射。`NtcShowcasePresenter` 将相机渲染到独立 RenderTexture，录制逐帧读取新渲染的图像。

```powershell
# 构建并录制同路径的两遍画面；Encoder 指向已安装的 ffmpeg
.\tools\Record-NtcShowcase.ps1 -Build -UnityEditor '<Unity.exe>' `
  -Encoder '<ffmpeg.exe>' -Output '<output directory>'

# 先输出原光线、补光和斜向日光三张同机位图片
.\tools\Record-NtcShowcase.ps1 -LightingReview -Output '<output directory>'
```

`-Project`、`-Player` 指定本地工程与展示 Player，`-Width`、`-Height` 指定输出尺寸。默认路径是仓库的 `unity-showcase` 与 `build/NTCinUnity-Presentation/NTCinUnity.exe`。普通启动 Player 即可操作界面；录制需要 ffmpeg。

构建时可用 `-CameraHeight 2.1` 调整展示副本的机位高度；不指定则沿用源场景相机。原场景不受影响。

| 输出 | 内容 |
| --- | --- |
| `Original.mp4` | 原材质向前机位 |
| `NTC-Direct.mp4` | 相同路径的 NTC 材质机位 |
| `NTCinUnity-Showcase-AB.mp4` | 左侧 Original、右侧 NTC 的同步对照 |
| `original.png` / `ntc-direct.png` | 两种材质的起点图 |
| `lighting-source.png` / `lighting-skylight.png` / `lighting-daylight.png` | 光照检查模式的同机位图片 |

录像、截图及运行日志输出到指定目录，本地示例场景和美术独立保存。

### 拖动对比与原理图

`Build-NtcReview.py` 将两路实际录像整理为本地对比页。拖动中间的分割条查看 A/B，进度条控制两路机位；暂停时对齐到相同录像帧。页面明确标注为 Unity 录制回放。

```powershell
python .\tools\Build-NtcReview.py --project '<Unity project>' `
  --recording '<recording directory>' --output '<review directory>'
```

依赖 Python 的 Pillow、numpy、matplotlib，以及本地 `ntc-cli`。`--cli` 指定 CLI，`--materials` 指定逗号分隔的材质名称，默认红挂毯、地面、石柱。当前源纹理提取适配 ClassicSponza 的 URP 材质约定，通过材质 GUID 找到输入贴图。工具重新解码当前 `.ntc`，生成五个 PBR 通道的输入、重建和差值图，以及真实潜变量与 INT8 权重预览。

原理图各节点可点击查看对应输入输出。`figures/` 保留 PNG/SVG 版流程图、压缩大小图、潜变量格式容量图和通道 PSNR 图；`review-data.json` 保留计算数据与口径。大小图比较同 NTC 分辨率的 UNORM8 有效通道+mip 与完整 `.ntc` 文件；格式图比较相同特征数量的 RGBA32 与 BGRA4 容量。

打开生成的 `index.html` 或 `Open-Review.cmd` 即可使用。如需 HTTP 预览，使用支持视频分段定位的服务器：

```powershell
python .\tools\Serve-NtcReview.py --directory '<review directory>' --port 8769
```

然后打开 `http://127.0.0.1:8769`。录制命令加 `-ReviewPage` 可在录像完成后自动生成对比页。生成的录像、贴图、图表和数据只保存在指定的本地输出目录。

`Export-NtcPortfolio.py --review '<review directory>' --output '<media directory>'` 整理网站所需资源：无损 WebP 通道图、720p 回放、原理图与图表、24 组绑定清单、训练参数和插值探针 CSV。依赖另加 `imageio-ffmpeg`。历史训练曲线取自保存的两份 CLI 日志；当前材质的重建质量和历史训练记录分别标注。网站上传脚本从本机 PicGo 配置读取 OSS 凭据，通过内容哈希生成对象路径；凭据不进入导出目录。
