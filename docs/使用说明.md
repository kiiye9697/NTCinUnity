# 使用说明

本说明对应 0.2；完整字段与契约见 [INTEGRATION.md](INTEGRATION.md)。支持范围和当前证据以 [项目主页](../README.md) 为准。

## 安装

宿主先创建 URP 项目并启用其 Render Pipeline Asset。已验证 Unity 2021.3.33f1、URP12.1.13、Linear、Windows D3D12；其他组合需要自行回归。

通过 Package Manager 安装本地 `unity-plugin/package.json`，或完整复制为 `Assets/NtcPlugin`。保留 `.meta`，不要同时安装两份。

离线烘焙需要 NVIDIA `ntc-cli`（构建见 [后端说明](../nvidia-backend/README.md)）、支持 Pillow 的 Python；部分 TIFF 需要 tifffile。Runtime 不依赖这些工具。

## 从材质到发布数据

1. 保存源材质为项目资产。临时材质没有持久化 GUID；标准 URP/Lit opaque/alpha clip Metallic 是 Direct 的支持范围。
2. 打开 `NTC / Bake Window`，检查 CLI/Python 路径。扫描覆盖全部 sharedMaterials 槽位，按材质对象去重。
3. 选择 bpp、训练步数和通道权重。默认100000步、16bpp偏向质量，不保证最省显存。单张输入图也可烘焙。源图搜索目录只在实际引用缺失时辅助定位，不替代资产引用。
4. Bake 后检查训练结果和最终发布结果。后台处理冻结任务；主线程验证容器并创建资产。失败不标记成功。`--gdeflate off` 不能移除，Runtime 不支持其解压。
5. 成功后检查 `Assets/NtcBindings` 下绑定/模板、`Assets/StreamingAssets/NtcData/<GUID_localId>.ntc` 和 `Assets/Resources/NtcOriginals` 下恢复材质。烘焙工作输出目录是中间产物，Player 使用已发布 StreamingAssets 副本。

MetallicGloss 的 R 为 Metalness、A 为 Smoothness，AO 读取源 OcclusionMap 的 G；需 AlphaClip 或 BaseMap-alpha smoothness 时保存 base alpha。源色彩空间、材质常量、功能开关与采样约定参与接入。不能将不匹配来源的 NTC 文件随意绑定到材质。

既有文件可选中源 Material，使用 `Assets / NTC / Bind Existing NTC To Material`。格式验证只能证明容器满足解码器契约，用户仍应确认数据通道与材质对应。

## 场景与运行

使用 `NTC / Add Scene Controller`。后续添加、重新烘焙或调整材质后，使用 `NTC / Rescan Scene Materials` 并保存场景；运行时扫描产生的修改不持久化。

从 Original 对照，分别验证 OnLoad、Tile Cache 与 Direct。Direct 是独立第四模式，旧 OnSample 指 tile cache。Direct 不支持的源特性显示原因并保留 Original。完整 Direct 与旧 BaseColor Unlit 诊断 shader 是不同入口。

`releaseOriginalTextures` 控制原图引用释放。共享消费者仍需使用的原图保留；切回 Original 从 Resources 恢复。不要对导入原图直接 Destroy。Resources 恢复副本会进入构建磁盘，但无需始终驻留 GPU。

## 构建与验收

保存场景，加入 Build Settings，确认 Controller、绑定资产和 shader 引用已序列化；绑定的 directTemplate 保留已知局部 shader variants。StreamingAssets 需落到本地文件系统；当前加载器未实现 Android 压缩 APK 或 WebGL URL 流式读取。

先验证实际 PBR 出图、材质开关/裁剪、阴影/深度、原图卸载与恢复，再测首次使用及稳态 GPU 性能。隐藏进程没有相机回调时，仅可验收资源/队列；不能发布帧率。

仓库 [tools/README.md](../tools/README.md) 解释各脚本、前置数据与产物。[Tests/README.md](../unity-plugin/Tests/README.md) 说明外部语料依赖。示例场景和25文件回归语料未授权随仓库发布；自己的工程可以直接烘焙，无需 Sponza。

## 排错

| 现象 | 检查 |
| --- | --- |
| 找不到 CLI/Python | 手动设置完整路径，先确认工具可独立运行并能 import Pillow |
| Bake 成功但 Player 没有数据 | 检查资产发布是否成功、重新扫描并保存、GUID StreamingAssets 文件是否随包 |
| Direct 回退 | 看 binding/Controller 原因，检查源 shader、透明/视差等特性及缺失通道 |
| 模板或 Shader 丢失 | 完整安装代码、Resources、Shaders 和 meta，不要复制孤立脚本 |
| 原图未卸载 | 检查 releaseOriginalTextures、其他场景/材质/脚本是否仍引用，查看分类账本 |
| 显存没有节省 | 统一分辨率与质量，比较当前导入 BCn、latent、权重及缓存总量，调整烘焙 bpp |
| 首次使用卡顿 | 记录新进程首次 draw+readback、warm draw 和驱动缓存状态；再用目标设备 profiler 定位 |
