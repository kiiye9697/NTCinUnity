# 使用说明

## 1. 获取仓库

NVIDIA RTXNTC 以 submodule 形式存在，克隆时需要递归拉取：

```bash
git clone --recursive https://github.com/kiiye9697/NTCinUnity.git
```

普通 clone 之后补拉：

```bash
git submodule update --init --recursive
```

## 2. 构建 NVIDIA 后端

`nvidia-backend/` 指向 NVIDIA 官方 RTXNTC 仓库。构建要求和命令以该目录自己的 `README.md` 为准。

本项目只需要它提供 `ntc-cli`，用于离线烘焙 `.ntc`。编译完成后，在 Unity 的 Bake Window 中手动选择 `ntc-cli.exe`，不要求把二进制复制进插件目录。

请注意：

- 后端使用 NVIDIA 自己的许可证；
- `ntc-cli`、`libntc.dll` 和 CUDA 都不是 Unity 运行时依赖；

## 3. 安装插件

将 `unity-plugin/` 复制到 Unity 项目的：

```text
Assets/NtcPlugin/
```

建议连同 `.meta` 一起复制。验证环境是 Unity 2021.3 + URP。

## 4. 烘焙材质

打开：

```text
NTC / Bake Window
```

### 4.1 设置

- `ntc-cli`：本机的 `ntc-cli.exe`；
- `Python`：能导入 Pillow 的 Python；
- `Bits per pixel`：默认 16，最大 20；
- `Metalness loss scale`：默认 24；
- `Smoothness/Roughness loss scale`：默认 16；
- `Output dir`：默认 `Assets/NtcPlugin/NtcData`；
- `Texture source`：只有材质没有直接引用贴图时才使用的约定搜索目录；
- `.ntc file name prefix`：通常留空。

格式转换需要 Pillow：

```bash
python -m pip install pillow
```

### 4.2 扫描

使用 Scene 或 Project 扫描。列表里的 Tex 数量是材质实际解析到的源贴图数量。少于两张时不能体现 NTC 的跨通道压缩优势，窗口不会按正常材质集处理。

URP Lit 的 `_MetallicGlossMap` 会拆成：

```text
R -> Metalness
A -> Smoothness
```

开启 Alpha Clip 的材质会尝试从 BaseMap alpha 提取 `AlphaMask`。

### 4.3 烘焙

开始批量烘焙后，窗口在后台任务中逐个调用 `ntc-cli`，不会把全部材质一次性塞进主线程。

实际命令包含：

```text
--gdeflate off
```

不能去掉。Runtime 没有 GDeflate 解码器。

输出通常为：

```text
Assets/NtcPlugin/NtcData/{MaterialName}.ntc
```

## 5. 场景控制器

通过菜单创建：

```text
NTC / Add Scene Controller
```

控制器默认：

```text
ntcDataPath   = NtcPlugin/NtcData
ntcFilePrefix = 空
```

进入 Play 后，面板提供三种模式和 PBR 通道检查。`F1` 控制面板显隐。

## 6. 模式检查顺序

建议固定按下面的顺序排错：

1. `Original`：确认场景基线；
2. `on-Load`：确认 `.ntc` 解析、MLP、坐标和 PBR 通道映射；
3. `on-Sample`：确认 tile 调度、缓存绑定和驱逐。

如果 Original 与 on-Load 不一致，先查解压和通道，不要先查流送。只有 on-Load 正常而 on-Sample 异常时，才应该进入 tile streamer 或回退 shader 的排查。

## 7. 常见问题

### 状态显示 not baked

确认 `.ntc` 文件名能和材质名匹配，并确认 `ntcDataPath` 指向实际目录。如果设置了 prefix，Bake Window 和 Controller 必须一致。

### 状态显示 GDeflate: rebake

该文件的 BufferView 使用了 GDeflate。插件不解码此格式，需要使用 `--gdeflate off` 重新烘焙。

### Metallic 或 Smoothness 接近常数

先比较源图和解压图的 min/max/mean/stddev。NTC 的 bpp 预算在全通道之间共享，高信息量的 Color/Normal 可能挤压单通道 mask。先提高该通道的 loss scale，而不是直接增加整个材质 bpp。

### Cutout 材质变成方板

确认 BaseMap 确实有 alpha、材质启用了 Alpha Clip，并重新烘焙生成带 `AlphaMask` 的 `.ntc`。旧文件无法靠 Runtime 自动补出缺失通道。

### on-Sample 是 Unlit

只有 fragment MLP 回退 shader 是 BaseColor-only Unlit。默认 compute/tile 路径绑定回 URP 材质，可以使用 PBR 输出。根据日志确认实际执行路径。

### Editor 正常，Player 找不到 `.ntc`

插件默认从 `Application.dataPath` 读取 `.ntc`，适用于 Editor。Player 工程需要使用 StreamingAssets、Addressables 或自定义导入器提供数据，并同步实现对应的文件读取接口。
